# v0.5 Tour

This page is the "what's new at a glance" for v0.5. For the **full source + render side-by-side** of each feature, head to the [[showcase/index|Showcase section]].

## v0.5 highlight: theme integration goes fully low-level

The core of v0.5 is making **third-party VitePress theme authors not need to know this plugin exists at all**:

- **All CSS moves into `@layer vitepress-allyouneed`** — ordinary CSS that you (or any third-party theme) write **automatically wins** over our styles, regardless of selector specificity or load order. `.wikilink { color: red }` really turns it red, no fighting required.
- **All `!important` removed** — no longer needed; you can override 100% of the time.
- **New `defineTheme()` factory** — zero-config one-line setup, or `defineTheme({ extends: thirdPartyTheme })` to nest someone else's theme.

> [!success] What this means for you
> After upgrading to v0.5, if you previously wrote `!important` or high-specificity hacks to override the plugin's styles, most of them can now be removed — ordinary CSS is enough to override.

## Graph experience upgrade

The relationship graph ([[views|see it in action]]) is smoother in this version:

- Node names **fade out smoothly** when zoomed out and emerge when zoomed in (consistent with Obsidian);
- **Stable hover hits** on nodes (a transparent hit ring was added, so even small nodes are easy to hit);
- Physics parameters retuned, so dragging / convergence no longer jitters;
- Container height adapts on mobile.

## Robustness

- View data loading now does full field validation, so a corrupted `vault-data.json` fails gracefully instead of crashing the whole page;
- Dates are uniformly formatted in UTC, eliminating SSR hydration mismatches;
- The dead-link pre-scan was switched to a linear scan, so a large vault won't hang on malformed input.

## Since the previous version (v0.4)

- **`folderLinkOrder`** replaces the old `autoFolderIndex` — the landing point for folder links (`same-name` / `index` / `readme` / `first-file`) can be controlled precisely, with no more writing of `index.md` files;
- **dev HMR auto-restart** — after adding/removing a `.md` or editing `_sidebar.md`, the sidebar / nav reflect it immediately;
- **Loosened section-number anchors** — `[[note#13]]` can match `## 13) Heading`, `## 13: Heading`, etc., but still won't mistakenly match the version number `13.5`.
